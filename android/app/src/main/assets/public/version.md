## V1.6 · Vue3 H5 版（当前版本）

本次为**平台迁移 + 功能增补**：把原先的微信小程序整体搬到 Vue3 + Vite 的 H5 项目，
使其能跑在浏览器、静态托管平台，并为后续打包 Android APK 铺路。

### 一、平台迁移：微信小程序 → Vue3 H5

**技术栈变化**

| 项目 | V1.5（小程序） | V1.6（H5） |
|---|---|---|
| 框架 | 微信小程序原生 | Vue 3 `<script setup>` |
| 构建 | 小程序开发者工具 | Vite 5 |
| 路由 | 小程序页面栈 | Vue Router（hash 模式） |
| 存储 | `wx.getStorageSync` 等 | `localStorage` 封装（`utils/store.js`） |
| 样式 | `rpx` 单位 | `vw` 单位（750rpx = 100vw，1rpx = 0.13333vw） |
| 弹层 | `wx.showToast/showModal` | `utils/ui.js` 发布订阅 + `ToastHost` / `ConfirmHost` |

**路由设计**：全部采用 hash 模式（`#/path`），因为静态托管与 Capacitor 的 `file://`
协议都无法处理 history 模式的服务端回退。

| 路由 | 页面 | 对应小程序 |
|---|---|---|
| `/` | 首页 | `pages/index` |
| `/setup` | 诗词分组 | `pages/setup` |
| `/bracket` | 分组与投票 | `pages/bracket` |
| `/vote/:id` | 诗词投票 | `pages/vote` |
| `/champion` | 最终结果 | `pages/champion` |
| `/library` | 资源库管理 | `pages/library` |
| `/game2048` | 2048 数字雅集 | `pages/game2048` |

**构建产物**：`base: './'` 输出**相对路径**引用，因此 `dist` 可以直接丢到任意
子目录下的静态托管，也可供 Capacitor 以 `file://` 加载。

### 二、2048 小游戏

#### 1. 双模式

| 模式 | 说明 | 方块上限 |
|---|---|---|
| 经典 | 新方块只出现 2 和 4（90% / 10%） | 65,536 |
| 疾掠 | 动态概率 + 阶段跃升（见下） | 2³¹ |

两模式各有独立最高分（`poem2048_best_classic` / `poem2048_best_rush`），
旧版单一最高分会在首次启动时自动迁移到经典模式。

#### 2. 封顶合并

两个已达上限的同值方块相撞时，仍合并为一个（两块并一块），但**不计分**、
也不再翻倍，避免数值溢出。例（经典上限 65,536）：`65536+65536 → 65536`。

#### 3. 疾掠模式：动态概率与阶段跃升 ⭐

按「场上最大数字」划分阶段，首次达到门槛即触发一次**阶段跃升**并永久切换概率表。

| 阶段 | 触发门槛 | 本阶段主块 | 概率表（主/次/三/四） |
|---|---:|---:|---|
| 0 | 开局 | 2 | 2:40% · 4:40% · 8:12% · 16:6% · 32:2% |
| 1 | 最大 ≥ 1,024 | 4 | 4:80% · 8:12% · 16:6% · 32:2% |
| 2 | 最大 ≥ 8,192 | 8 | 8:80% · 16:12% · 32:6% · 64:2% |
| 3 | 最大 ≥ 65,536 | 16 | 16:80% · 32:12% · 64:6% · 128:2% |
| 4 | 最大 ≥ 262,144 | 32 | 32:80% · 64:12% · 128:6% · 256:2% |

**通关门槛**：场上出现 **1,048,576** 即通关。

**跃升时的清除与合成规则**

1. 清除棋盘上**所有等于上一阶段主块**的格子，统计数量 `count`
2. 每两个旧主块合成一个当前阶段主块：生成 `floor(count / 2)` 个，随机放入空格
3. `count` 为奇数时，余下 1 个旧主块**直接消失**（不返还）
4. 跃升后新块生成立即切换到新阶段概率表

举例：阶段 1 → 2 时清除所有 4，每 2 个 4 换 1 个 8。

**关键实现顺序**：跃升必须在「生成新方块」**之前**执行，
否则新方块仍会按旧阶段概率生成（表现为「已到阶段 2 还在刷 2」）。
实现中把跃升检测放在 `move()` 内 `addRandom()` 之前，并用 `while` 循环
兼容读档后阶段与棋盘不同步的情况。

#### 4. 阶段可视化

- **阶段胶囊**：模式栏旁显示 `阶段 N · 主块 X`，终章显示「终章 · 已通关」
- **分级光效**：阶段 0 绿 → 1 金 → 2 青 → 3 紫 → 4 粉（脉冲），
  胶囊与棋盘边框同步变色
- **通关表现**：棋盘彩色流动边框 + 通关方块彩框 + 渐变横幅 + 提示

#### 5. 操作与交互

- **手机**：滑动棋盘（触摸手势，`touch-action: none` 防止浏览器抢去滚动页面）；
  阈值 16px，斜滑（两轴位移相等）不触发，多指时不当作滑动
- **电脑**：物理方向键 / WASD / 点击虚拟方向键
- **撤回**：撤回栈最多 20 步
- **无效滑动**：棋盘尚有空格时仍算一回合并生成新方块（原方块不动）；
  棋盘已满则不做任何事
- **自动存档**：每步即时写入，手机切后台 / 关标签页 / 硬刷新都不丢进度；
  「返回」与「重开」拆成两个按钮，避免误触丢分后无法返回

#### 6. 布局

所有屏幕尺寸统一为**棋盘居中、操作区在下**的上下结构，左右对称、视觉重心居中。
棋盘尺寸同时受视口宽度与高度约束，保证方向键与「撤回/重开」始终在首屏内，
无需滚动即可操作。

### 三、对阵图（BracketPage）

- **缩放**：电脑滚轮缩放、手机双指捏合缩放，范围 40% ~ 250%（步进 20%）
- **平移**：鼠标拖拽（`grab` / `grabbing` 光标）与触摸滑动
- **缩放控件**：`−` / 百分比（点击复位到 100%）/ `＋`
- 缩放时以视口中心为锚点，避免放大后内容跑出视野

> 实现要点：`transform: scale()` 不改变布局尺寸，因此外层用
> 一个显式尺寸的 spacer 撑开滚动范围；`transform-origin: 0 0` 保证坐标换算简单。

### 四、诗词分组（SetupPage）

「生成分组」按钮改为**悬浮固定**在页面底部（`position: fixed`），
随页面滚动始终可见，不需要滑到底部才能点；同时在列表末尾留出等高占位，
避免遮挡最后一首诗词。

### 五、测试

| 类型 | 范围 | 结果 |
|---|---|---|
| 单元测试（Vitest） | 对阵图逻辑 34 项、疾掠阶段机制 23 项 | **57 / 57 通过** |
| 端到端（无头 Chrome + CDP） | 跃升触发、概率切换、通关、存档往返 | 24 / 24 通过 |
| 端到端 | 四个阶段连续跃升 | 36 / 36 通过 |

疾掠阶段机制的单元测试覆盖：门槛边界（含 `<` 与 `>=` 的临界值）、
各阶段权重和恒为 100、阶段 0 分布回归、清除/生成数量守恒（400 轮随机）、
奇数余量处理、概率抽样分布（50 万样本）。

### 六、构建与部署

```bash
npm install
npm run dev        # 本地开发
npm run build      # 产出 dist/（相对路径，可直接静态托管）
npm test           # 运行单元测试
```

`dist/` 可直接上传到任意静态托管（Vercel / Cloudflare Pages / 对象存储）。
因使用 hash 路由且资源为相对路径，无需额外配置重写规则。

**已预留脚本**（Capacitor 打包 Android APK，尚未启用）：

```bash
npm run cap:sync      # 构建 + 同步到原生工程
npm run cap:android   # 构建 + 同步 + 产出 debug APK
```

## 已知限制与后续计划

**当前限制**

- `V1.6` 为纯前端应用，数据保存在浏览器 `localStorage`，不同设备之间不互通
- 尚未提供 PWA 离线能力（断网无法打开）
- Android APK 尚未打包

**后续计划**

1. **PWA**：加入 Service Worker 与 manifest，支持加入主屏、离线可用
2. **Capacitor 打包 Android APK**：`web/` 已配置好 `base: './'` 与 hash 路由，
   可直接走 `npm run cap:android`
3. **OTA 热更新**：配合 Capacitor 实现不发版更新前端资源
